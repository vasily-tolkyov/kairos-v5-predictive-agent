## 复现与修复

`ExperienceMedium` 在局部分区不支持预测时，会退回整体回归。
此前它仅在局部已有至少八条校准记录且准确率不足时撤销支持，
因此不足八条记录的区域反而可以借用整体准确率。合成复现中的稀疏区域
只有六条校准记录，仍得到受支持的位移预测。另一个复现证明：
局部分区已经判定输入超出观察范围，回归仍可绕过这个判定。

现在回归同时要求所有可能的局部区域均在观察范围内、至少八条真实的
更新前校准记录、准确率至少 0.8，并保留回归自身的原有支持门槛。
样本不足的效果仍可用于明确标注的假设探索。相同机制获得更多真实窗口后
可以得到支持；定向检查还验证了随后 512 次另一情境更新后的保持、
容量上限、冻结查询无写入和检查点恢复一致性。

数值点预测此前按容差计分，但输出区间主要是已存结果的最小/最大值，
没有计入更新前预测残差。两个连续响应复现都出现“受支持但实际值落在区间外”。
现将最近最多 32 条校准记录还原到观测量单位，取绝对残差的经验 90 分位数，
分别扩大局部读出和回归读出的区间。所有保留的真实结果仍在最终区间中。
截断为 20 的误差分数只表示下界；如果选中的分位数被截断，就拒绝以它
构造有限误差半径。这里的 90 分位数是有界校准历史的工程选择，
不构成未来 90% 覆盖率、完整可能性集合或一般外推保证。

第一版使用近期最大残差，受旧分区的一次较大误差影响，令原有三阶段用例
额外规划一次移动。这份失败日志保留；现有三阶段断言、六次实际确认、
十阶段用例、零时间预算检查和原生 100/50 ms 规划预算均未放宽。
支持判断和区间是在读取时推导的；没有改写历史窗口、快照格式、误差记录或权重。

## 合成连续响应对照的收益和代价

使用两个固定采样种子、两种连续响应斜率，每组训练 320 个合成窗口，
再冻结模型检查未用于训练的 19 点网格。此诊断为开发者已知机制，
不是盲测或陌生 Minecraft 世界。两实现的学习快照逐字节摘要相同。

| 种子 / 斜率 | 基线：支持 / 区间命中 | 修复：支持 / 区间命中 | 基线 / 修复平均区间宽度 |
| --- | ---: | ---: | ---: |
| 123 / 0.2 | 19 / 17 | 18 / 18 | 0.0100 / 0.0240 |
| 123 / 4 | 19 / 16 | 16 / 16 | 0.2151 / 0.4780 |
| 456 / 0.2 | 19 / 16 | 14 / 14 | 0.0115 / 0.0235 |
| 456 / 4 | 19 / 19 | 16 / 16 | 0.2488 / 0.6820 |

共 76 次查询，基线授予 76 次支持、68 次命中；修复授予 64 次支持、64 次命中，
另外 12 次不授予支持。所有受支持的位移仍有一致方向。
这说明在此诊断中支持更谨慎、区间更宽；总命中数也减少了四次。
不能据此声称可用预测数量增加、原生任务保持已修复或规划成功率提高。
完整结果及构建哈希见 [continuous-comparison.json](prediction-calibration-evidence/continuous-comparison.json)。

在分别构建基线和候选后复现此诊断，输出必须使用新文件名：

```sh
node scripts/compare-synthetic-calibration.mjs /path/to/baseline/dist dist evidence/new-calibration-comparison.json
```

## 当前限制与下一步

GitHub 连接可读取草稿 Release 的元数据和资产摘要，但当前提供的下载接口
不能取得其二进制附件；直接下载原生补充 ZIP 返回 HTTP 404。本环境只有
Java 17，且没有发现 Minecraft 1.21.4 服务端。因此没有重放原生 frame 19、
没有加载那一对 5098/12321-write 模型，也没有新原生学习或冻结保持试验。
不发布草稿 Release、不更改权限，也不以较旧检查点替代指定对照。

下一步仍遵守 [既有原生协议](native-evidence-2026-09-13/README.md)：

1. 在可读取原始附件的环境取得并校验三个包，保留每个原始清单和全部失败记录。
2. 用 `diagnose-recorded-retention.mjs` 和 `profile-recorded-planning.mjs`
   对完全相同的原始 frame 19、目标、前后模型分别运行基线与候选。
   报告目标轴支持覆盖、区间命中、宽度与规划长度；不要只看静态通道平均分。
3. 保持原简单和平场景和原冻结对照预算；将此候选冻结为新的执行副本。
   新学习必须使用已修正的动作释放，保留实际释放收据；启动前固定输入
   session SHA256，等待准备完成并独立核验世界文件。
4. 在新增物理学习前后重做相同初始世界的冻结任务保持对照，再决定如何修复
   预测覆盖与情境保持。不能通过减少校准要求、放宽目标或提供路线取得成功。

原 PR 的长期开放世界学习与开放因果多阶段验收仍未完成；本轮修复的是
预测支持和区间的可解释缺口，不是那一项整体能力验收。
