# 工作包 A：动作开始帧与执行前预测

基线提交：`fb3c40a8e172e092ca6ba9a69eebc2836e255b36`。本目录记录的是该基线之后的工程反例与回归，不是原生自主探索能力证明。工具链为 Node `v24.19.0`、TypeScript `5.9.3`。

## 已修复的归因错误

原适配器已经会重新绑定当前动作，介质也已经从实际事件首帧学习；这些机制被保留。错误在会话层：规划开始时的预测仍被拿来比较后来动作的结果，并可给 `forecastAdvanced`、局部反驳或日志中的支持计数归因。等待期间的被动变化可能因此被算成动作效果。

新增可选的同步 `beforeExecute` 契约。仅当身体明确声明 `synchronousActionStart === true` 时，适配器才使用它。顺序是：清空此前的真实被动窗口；获取当前实测帧与动作绑定；会话按时间顺序消费被动窗口；从同一介质只读重预测；决定是否执行；身体在首次 `await` 前捕获开始帧。支持已撤销的原受支持计划会被拒绝；假设保持假设，不升级成支持。

预测在调用身体执行之前保存在会话本次调用的局部状态中，后续反馈更新不能重新计算并替换它。`SessionDecision` 的持久日志仍在动作结束后写出；这项修复不宣称具备进程崩溃前已经落盘的预测日志。

实际收据的首帧必须与执行前捕获的完整测量摘要一致，摘要包括原始感觉与感知内容。仅序号相同或身体属性相同不足以认证预测。被动窗口必须真实、有序、结束于开始帧之前；已消费窗口按 ID 重传时摘要变化会被拒绝，不能通过去重绕过来源检查。

## 审计字段

| 字段 | 含义 |
| --- | --- |
| `planningObservationSequence` | 原搜索使用的实测帧序号 |
| `predictionObservationSequence` | 已验证预测所使用的动作开始帧序号 |
| `predictionFresh` | 预测输入与实际事件首帧完整相符 |
| `predictionInvalidation` | 支持撤销、开始帧变化或开始帧无法验证 |
| `predictedSteps` | 同步重绑定后只记录重新预测的首步；旧多步分支不会继承新首帧的认证 |
| `planLength` | 搜索当时的分支长度；单独使用它不能证明实际执行时存在受支持的多步方案 |

`forecastAdvanced` 和局部 `refuted` 只给经实际首帧验证的预测归因；局部反驳绑定实际开始情境。无法验证开始帧时，也不能把连续非终态作用累计成已证伪的失败试探。真实目标状态的独立确认继续保留。

## 明确保留的限制

`MinecraftBodyConnection` 在独立 worker 中维护真实时钟，`takePassiveEvents` 和 `execute` 跨线程返回 Promise。它没有同步开始能力。适配器正常等待其被动数据并继续异步执行；不会暂停物理线程，也不会在控制线程伪造同步开始预测。实际事件首帧若相对原搜索帧发生变化，旧预测的比较与动作归因被撤销。

因此，本改动完成同进程开始帧认证与 worker 过期证据的保守排除，**没有完成 worker 在负载下持续获得新鲜受支持动作预测的协议**。该能力仍需要后续有明确状态版本和延迟预算的跨线程执行设计，不能以本目录测试宣称全部工作包 A 或 B/E 已完成。

旧 synthetic 环境若没有事件收据，保留既有结果比较兼容接口，并明确标为 `predictionFresh: false` / `unverified-action-start`；它不进入新的可信预测成功/失败归因。若旧环境有事件且首帧与规划输入完整相同，则可正常比较。原测试的断言、目标和预算没有放宽。
