## 结论

原型不是完全没有自主学习能力：仓库保存了一组保留经验优于擦除经验的真实移动任务结果，也有实际探索造成环境变化的记录。但是，当前证据仍不足以认定它实现了可靠的开放世界自主学习或开放因果多阶段规划。最有辨识力的反证不是某一项软件测试失败，而是：继续学习一小时后，同一初始场景中原来能完成的任务不再完成，受支持计划归零；改正动作释放时长后仍未恢复。

下一阶段应把“可用且可信的预测”作为核心验收对象，将连续状态、情境保持、主动求证、经验形成的时间抽象接入同一预测闭环，而不是继续添加针对挖掘、跳跃、绕路、饥饿或某个任务的补丁。

这是一份源码审查、实际执行的软件检查、归档真实游戏数据的新增离线诊断，以及下一阶段设计。**本次没有成功启动 Minecraft，新增真实游戏动作数为零。不能把下文的历史实机记录或离线重放计为本次实机测试。**

两个重要限制：

第一，成功的 40 动作任务中，仅 2/25 个受支持的目标轴数值预测落入其声明区间。能朝正确方向移动，与预测数值可靠，是两件事。应保留真实成功，同时撤销“因此预测已经充分可靠”的推论。

第二，仓库中的十阶段合成组合测试可以证明特定构造下的组合逻辑，但它使用确定的展开预算，并显式取消墙钟截止时间；原生运行仍使用 100/50 毫秒规划预算。不能把合成十阶段成功写成真实 Minecraft 十阶段规划成功。上述普通难度失败也不能单独归咎于敌对生物，因为和平环境中的简单任务保持和围栏退出仍失败。

## 3. 新增缺陷：陌生类别情境被当作已知分支

**优先级：高。状态：当前源码上已复现，未改生产代码。**

位置：`src/contextual-readout.ts:163–200`，尤其对 `outside` 的判断与 `goesLeft` 分支选择；随后 `ExperienceMedium` 和 `ExperienceAgent` 消费其支持状态。

复现使用 256 个合成实际窗口，只训练 A、B 两种感知情境：A 下同一动作造成 z 增加 1，B 下 z 减少 1。之后冻结模型，查询从未出现过的 C。

| 查询情境 | 是否训练过 | 输出 z 区间 | `supported` | 对 `z < -0.5` 的计划 |
|---|---:|---|---:|---|
| A | 是 | [1,1] | true | 无达标计划 |
| B | 是 | [-1,-1] | true | 单步 `predicted-goal` |
| C | 否 | [-1,-1] | true | 同样生成单步 `predicted-goal` |

原因不是已经学会“C 与 B 相同”，而是类别树以“是否等于 A”为分支，C 自然落入非 A 分支。当前代码只对数值分支验证观察范围，没有为参与预测的类别分支维护已观察域或未知类别状态。于是 B 分支的校准证据被授予 C。

A/B 对照和冻结摘要检查均通过；“未知 C 不得借用 B 的支持证据”的断言失败。文件为 `probes/categorical-support.mjs`、`evidence/categorical-support.json` 与 `.log`。这是合成软件反例，不是新的 Minecraft 失败，也未证明它是 R6 保持退化的根因。

修复应是统一的证据域机制：类别分支保存真实观察过的域，未知值保持未知或多分支假设；局部读出和回归后备必须遵守同一域约束。未知情境可以提出假设、选择真实试探，但不能获得“已支持”的证书。还要验证类别改名/排列、恢复快照、缺失情境、真实增加 C 样本后恢复支持。不能简单禁止一切泛化，也不能靠枚举 A/B/C 的特例修复。

## 4. 当前“物理介质核心”的身份必须说清

`src/prototype.ts` 的默认公开入口使用 `ExperienceMedium`，明确将旧 lattice API 留作检查点检查与对照。当前新介质是数值模拟的速率神经元/塑性读出实现：按动作选择电路，最多 32 个连续输入、16 个 tanh 隐单元，读出使用递归最小二乘等更新，并由从真实响应诱导的上下文树补充。依据：`src/experience-medium.ts:10–27,158–214,255–333`、`src/prototype.ts`。

它不是仅凭名字就能继承旧分布式传播介质的所有验证结论；也不应因为没有沿用旧类名就被武断否定。正确做法是冻结两条谱系及其证据，明确本阶段以哪个实现为基线，再在同一真实窗口和同一任务协议上检验扩展。

当前实现有长期参数、感知跟踪、世界记录，**并非毫无记忆**。但介质的瞬时 `#field` 计算没有一个随每帧演化、容纳未显露状态的递归工作状态；主学习路径从动作窗口首帧与末帧形成目标。中间帧被验证并可能影响感知跟踪，却没有因此自动成为完整的时间状态建模。

因此“稍早看到一个线索—线索被遮挡—稍后依据它行动”“持续挖掘的中间状态”“等待导致迟发变化”等问题，不能仅靠把搜索深度调大解决。必须把时间状态本身作为预测介质的一部分。

## 5. 新增真实窗口离线对照

输入为归档 V50 模型（2339 次历史写入）及随后 V51 前 32 个动作窗口。按归档顺序选择，不按结果挑样本；包含 8 类动作、11 个身体位置发生变化的窗口。比较保存的 ea097eb 原始源码读出与当前主分支读出，双方使用同一个原始检查点。

第一次试图严格匹配原 V51 初始摘要失败，日志保留。原因核查发现：V50 使用 `ContextualReadout1`，V51 当时的 contextual-readout 源码摘要不同于稍后保存的 ea097eb；当前加载转换为 `ContextualReadout2`。因此后续实验明确定义为**新离线读取对照**，不是历史 actor 的精确复演，更不是较晚 R3/R6 的 5098/12321-write 对照。

后续检查要求两臂恢复后的学习摘要相同；原始神经网络数值、上下文真实样本与写入计数不变；所有查询前后学习摘要不变。上述检查均通过。摘要和初次失败均保留。

| 32 窗口中的读取指标 | 保存的 ea097eb 读出 | 当前主分支读出 |
|---|---:|---:|
| 受支持的位置分量 / 区间命中 | 62 / 61 | 34 / 34 |
| 三个位置分量全部受支持的窗口 | 15 | 8 |
| 三个位置分量全部支持且命中的窗口 | 14 | 8 |
| z 轴受支持 / 命中 | 21 / 21 | 10 / 10 |
| 位置实际变化窗口中，z 轴受支持 / 命中 | 5 / 5 | 2 / 2 |
| 新动作 / 新写入 | 0 / 0 | 0 / 0 |

这表明在这一小段数据上，当前读出更保守，少了位置区间错误，也少了大量受支持输出。不能据此称原生成功率提高。全部比较条目还包括物体、视域及后续不可观察的通道；报告 JSON 保存比较器原始口径，不把不可观察条目都称为数值预测错误，不以静态身体通道平均分代表能力。

另一个直接观察：该旧模型的 **74/74 个连续电路已达到 32 输入容量**。这 32 个窗口的身体输入有 28–38 个当前特征，某些电路遗漏 0–6 个当前特征，常见缺项包括注视物体的相对几何。代码确实在容量满时忽略新连续受体，但上下文读出仍接收完整输入。因此不能说“整个系统只看 32 个特征”，也不能把这项旧检查点发现直接当作较晚 R6 的根因。它指出的是一个明确应审计的表示与学习顺序依赖。

## 6. 距离最终目标的结构性差距

### 感知与持续对象

当前是工程化低分辨率 RGBD、近似实体/流体光学、身体自身信号和可见快捷栏，不是完整客户端视觉。传感器用引擎几何形成可见图像，与向学习器泄漏隐藏目标解法不是同一回事，但这是实验边界，必须明示。

已有自运动补偿、注意与遮挡处理值得保留；缺口是跨遮挡/重访的持续对象信念、对身份歧义的多个假设、相机变化与物体变化的长期一致区分，以及真实 UI 操作。当前身体边界未证明完整背包/合成/工作台界面交互，因而不能声称具备 Minecraft 开放任务的一般操作完备性。

### 情境保持与泛化

数值范围/局部校准修复缩小了虚假支持，但支持覆盖下降后是否能通过有效新经验重新增长尚未得到实机证明。要分辨：过去的错误支持被正确撤销、真正的知识干扰、上下文别名、稀有情境样本淘汰、动作时序污染，分别贡献了多少。

不能仅凭学习后失败就断言“神经介质灾难性遗忘”。同样，不能以校准更保守为由接受全部停止规划。需要在保留可靠性的同时建立足够的行动覆盖。

### 自主探索

`ExperienceSession.#proposal` 主要按空间访问新颖性、位移和步数评分，深度 6、beam 8、约 50 ms；生成的是空间目标。这是可运行的探索基线，但还不是“找出决定当前未知结果的因素”。`explorationDrive` 已利用局部不确定与学习进展等信号，不能说完全没有求知机制；缺的是将这些信号组织成能区分竞争预测的连续实验，并在获得答案后停止无效重复。

### 多阶段规划

当前支持有限的状态搜索和学习到的未来动作可用性；不是硬写全部解法。但搜索节点仍主要对应原始动作，优先级为目标残差加每步常数代价，缺少从真实轨迹形成、带启动条件和终止条件的时间抽象，也没有足够的持续隐藏状态使远期前提可靠。

应允许为了最终目标暂时远离目标、观察不确定的前提、执行未立即改善坐标的操作；不是添加“遇到障碍先挖再跳”的模板。合取目标本身、连续移动很多次、探索偶然成功，都不能作为开放因果多阶段规划的证明。

### 需求与任务调度

PR #2 的维护/任务 1:1 轮换解决了某类永久饿死问题；实际窗口进展记账也修复了真实错误。这些是合理的执行保障，不应一概叫作坏补丁。但是，轮换和 FIFO 没有学会比较紧迫度、可恢复性、失败后果与任务机会成本；不能继续叠加针对更多情境的调度分支来冒充自主决策。

### 计算和长期状态

当前 93 源文件共 29327 行，含大量历史分布式实现；8 个主要活跃模块合计约 2939 行。复杂度的核心不是“代码已经太多所以重写全部”，而是两条模型谱系、若干近似读出、证据来源与支持条件难以统一追踪。

世界记录有显式容量，但全局电路/输出通道/类别字典并非因此获得统一的字节预算。规划调用前检查截止时间，单个同步预测本身仍可能越过剩余预算。尚不能仅凭静态代码认定生产内存泄漏或定量时延根因；必须在固定工作负载上量测总资源、p95/p99、执行中身体漂移和持久化成本。

## 7. 必须保留的正确机制

真实感知/动作窗与想象查询分离；禁止目标、配方、路线、引擎身份和预测结果成为实测标签。逐字段支持/未知状态、数值区间、缺失上下文拒绝与假设标记应保留。冻结模型、擦除经验、同世界配对、延后真实确认、原始窗口和失败日志不可变，同样必须保留。

动作释放时长、纹理缺失、感知遮挡等装置错误需要修复。禁止任务解法模板，不等于禁止正确的传感器/执行器实现；由真实经验诱导的条件关系，也不等于开发者写入的规则模板。

工程下一阶段的设计、接口、迁移顺序及验收协议见 `ENGINEERING_NEXT.zh-CN.md`。
