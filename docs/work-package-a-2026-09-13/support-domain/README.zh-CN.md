# 工程包 A：逐响应证据域修复

此目录记录 `contextual-readout.ts` 的独立修复与验证，基线提交为
`163c991cf8ea1b14821e4aec4a61ee003858ea08`。这是合成软件证据；新增
Minecraft 自主试验、原生学习窗口均为零。动作收据与执行前重绑定由本轮其他修改负责。

## 修复

只对真实响应已识别为相关的字段约束适用域。类别分支保存实际出现的取值，
陌生 C 不再因为“不等于 A”而取得 B 的支持。一个新 C 样本也不能借用 B 的
校准数；共享响应叶中的类别，分别使用自身实际更新前预测误差取得支持。
局部常数读出和回归后备共同遵守域判定，后备读出的原有校准门槛保持不变。

缺失相关字段仍为未知。缺失字段的新实测保存在原始有界样本中，但不会被
暗中分配给“不等于 A”的分支，也不会使整个已学习分区直接坍塌。
无关新字段、已证明不影响当前响应的类别变化，不会无条件撤销全部支持。

数值域去掉原有固定 ±0.1 单位的外推余量，仅允许浮点舍入误差；检查点值、
区间顺序、有限性、点与区间一致性，以及整个区间是否在适用域中。
同一数值字段的连续阈值是在已观察区间内继续分区，不能用每个子节点的样本
极值制造相邻实测点之间的“空洞”；跨另一依赖后重新验证局部数值域。
跨越不同后果的区间仍不能选择其中方便的一侧。

快照仍为 `ContextualReadout2`：类别域与按类别归属的叶统计都由保存的真实样本
和结构重建，没有伪造新误差、样本或写入数。恢复旧快照采用的是本轮新读出
语义，不能冒称原历史 actor 的精确复演。叶统计缓存仅保存完整已知路径上的
非空实际样本组合，每叶缓存数不超过该叶实测数；旧叶替换后可回收。
缓存不参与长期快照或学习摘要。

## 查询成本

`compare-query-cost.mjs` 用同一固定合成记录分别构建基线和候选，每组七轮，
每轮 10,000 次已知输入查询，顺序交替；不含原生规划、学习更新和 Minecraft。
最终原始数据及编译产物摘要在 `query-cost-final.json`，前一个候选测量也保留。

| 场景 | 基线中位数 | 候选中位数 |
|---|---:|---:|
| 数值分区 | 8.95 ms | 10.76 ms |
| A/B 不同类别叶 | 8.96 ms | 13.11 ms |
| A/B/C、B 和 C 共享响应叶 | 8.58 ms | 12.84 ms |

每轮 10,000 个已知查询均保留支持，所有查询前后快照一致；候选增加约
0.18–0.43 微秒/查询。共享响应场景三个类别首次查询共 0.076 ms。
这些数字只能衡量此固定 readout 工作量，不能证明原生 100/50 ms 规划截止时间
或长期训练吞吐已经达标。

复跑示例（两个参数均为编译后的 `src` 目录）：

```sh
node docs/work-package-a-2026-09-13/support-domain/compare-query-cost.mjs evidence/builds/baseline/src /path/to/candidate/src
```

该修复不证明所有潜在因果条件都已被发现，也不修复对象对应歧义、连续状态、
长期保持或开放多阶段任务能力。没有曾产生可辨响应差异的隐藏条件，仍是原型
尚需通过进一步真实探索识别的不确定性。
