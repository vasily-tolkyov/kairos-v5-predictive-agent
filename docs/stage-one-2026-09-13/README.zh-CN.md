# 第一阶段：让一小段真实移动经验有用

状态：2026-09-13 按用户最新阶段调整收敛；尚未开始本阶段实机试验。长期目标保留，但本阶段不扩展长期运行、复杂地形、多阶段、合成或生存。旧方向已暂停，当前没有在运行的 Minecraft 实验；R10 的原始输出、故障模型和停止世界已保存。未验证的后续优化封存，不进入本阶段执行版本。

**要学会什么。** 在一个小型、平坦、和平的真实 Minecraft 场地里，身体自己试走，学到“在当前可见空间和当前动作下，实际能移动多少”。例如同样短按前进，面前空旷时有位移，接近实墙时位移受限。随后只给短距离终点，从事前固定的不同起点或朝向出发；让经验帮助它少做无效动作并更常到达终点。训练不提供测试路线、转向顺序、碰撞答案或测试成功标签。

**现在最妨碍学习的缺陷。** 当前通用闭环花在全场景拟合与搜索上的时间超过实时动作窗口：R9/R10 连续两轮针对计算积压的修改仍触发消费者落后，分别只有 4/9、2/10 次完成决策实际执行，目标和受支持预测均为零。完整性失败使这些比例不能成为改善证据。停止这一重复优化方向；本阶段需要测量并限制单次学习/选择成本，让真实动作先形成足够数据，而不是继续增加外围机制。连续状态的定时多步预演也未完成，本阶段不依赖它。

**保留什么、只改什么。** 已有原生服务器、匿名感觉接口、真实动作收据、精确开始帧拒绝、原始窗口记录、停止存档及独立结果核验可以复用。只允许与短距离移动直接相关的局部预测与单步选择，以及固定场地和配对评估入口；学习输入必须来自身体感觉，输出必须来自真实动作后果，任何新预测器单独标识，不能继承旧模型的支持。先检查现有端点读出是否足够；只有明确的实时或解释障碍才引入更小的局部模型。保留旧实现，不把本阶段简化模型冒充完整连续经验系统。

**怎样区别学会与碰巧。** 首次运行前登记场地、训练方式、不同测试起点/朝向、固定终点、每回合动作/墙钟预算和成功标准。主要比较同一初态、目标和预算下的“学后冻结”与“擦除冻结”；每个配对从独立的原始停止世界副本开始，交替组别次序，重复运行，测试期间不更新模型。必要时另登记在线诊断组。报告所有回合成功率、到达成本、动作执行/拒绝、用于选择的位移预测覆盖与误差，缺失预测和错误不能从分母排除；核对冻结摘要和真实收据。只有重复配对显示清楚的任务收益、关键预测基本吻合且没有路线泄漏，才通过阶段验收。

**让这一阶段收敛。** 每轮只检验一个事前假设。先检验“小场景加单步闭环能否及时执行并产生可用的动作后果”，再检验“这些经验是否在固定配对测试中改善行为”。同一障碍连续两轮针对性修改仍不改善关键指标，即停止重复，交付失败原因和替代设计，等用户决定；不增预算、不换复杂场景延长尝试。进度始终说明已经证明、主要障碍、下一实验问题和剩余验收缺口。
