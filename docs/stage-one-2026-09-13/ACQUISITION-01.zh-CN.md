# 首轮：动作与完整性达标，学习耗时未过线

假设：小场景、八个感觉输入和两个位移输出的单步原型，能在原预算内及时获得真实移动经验。原始登记为 128 次决策、240 秒；学习耗时第 95 百分位上限 20 毫秒，不能事后改线。

实际完成 128 次决策、124 次动作、124 次合格四物理步窗口，95.687 秒，无遥测缺口。4 次拒绝保留。43 个窗口确实受阻、81 个有移动。原始窗口与开始帧逐一相符；独立私有复算得到相同最终模型，仅作核验，不增加真实经验。服务器于 2026-09-13T13:43:36.061Z 停止，世界归档 SHA-256 为 `f462ddddd912911b201247d268e4a2989f61422dcd119581a04e655dc139e93f`。

选择加开始准备的第 95 百分位为 3.021 毫秒，但学习为 27.828 毫秒。**计数与完整性通过，耗时门槛失败，不启动依赖它的冻结配对。** 这支持“小原型能及时执行多数动作”，没有支持全部获取门禁或任务验收。

124 次执行中，4 次无预测，111 次只有未受支持的预测，9 次受支持且全部吻合；120 次有数值预测中 82 次误差不超过固定的 0.15 格。不能用 9/9 遮盖仅 9/124 的支持覆盖。实际选择为前进 12、后退 12、左移 62、右移 38，探索偏向尚不稳定的侧移。训练没有提交测试终点，任务收益尚未测量。

下一轮只检验一个原因：私有 CPU 记录显示整段感觉记录的规范排序/序列化占主要学习成本，分区拟合占比较小。V2 直接摘要实际归档的原始 JSON 字节；同 ID 不同字节仍冲突，校准、输入、输出、动作、场地和预算不变。先逐窗口核对学习与预测一致，再实机检验耗时。支持覆盖低是另一障碍，不能把字节校验提速称为它已解决。
