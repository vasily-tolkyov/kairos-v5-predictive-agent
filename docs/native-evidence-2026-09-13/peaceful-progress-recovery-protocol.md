# Peaceful progress-recovery comparison

Registered before the one-hour predecessor ends and before either comparison
starts, on 2026-09-12 UTC. This is a controller-repair experiment, not a new claim
of causal multistage planning or additional learning benefit.

Predecessor: the normally stopped peaceful-natural-online-long run. Preserve
its existing pending goal and baseline. Create two copies of its verified world
archive and exact final session. Check equal session and world-tree hashes.
No teleport, inventory edit, task reset, goal replacement or extra actions.

Control: immutable execution-builds/peaceful-r3 (historical-best progress rule).
Candidate: immutable execution-builds/peaceful-r5-progress (actual action-window
progress rule, plus copied intention audit metadata). Run sequentially in that
order, with the same 96-new-decision / 480-second budget, frozen dynamics and
affordances, native 100/50 ms planner limits, and stop on verified terminal
success. Frozen state still permits measured task feedback and motor habituation.
The two actor manifests must be preserved. Equal server/world bytes do not imply
deterministic wall-clock scheduling, so this is one matched pair, not a precise
effect estimate or exact replay.

Primary checks: original active and passive window hashes; unchanged learned
digests; actual saved-player position; six distinct later observations for any
goal confirmation. Report goal outcome and residual/displacement separately.
Mechanism check: count actual action-window residual reductions, which were
credited, and whether subsequent cooldown occurred. In candidate logs, reconstruct
progress independently with the goal evaluator and original action windows.
Neither unchanged positions nor numerical drift counts as useful progress.

Keep both outcomes, including failure or ambiguous controller benefit. A repaired
progress flag alone does not demonstrate improved task completion, learned
prediction calibration or causal multistage competence.
