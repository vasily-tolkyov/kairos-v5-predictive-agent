# Minecraft 实测：当前重构未达到目标

2026-09-10。学习核心为 `7f9a8fc`，实际运行官方 Minecraft Java 1.21.4。后续只修复了连接线程和评估程序，没有改变学习权重更新、探索策略或规划算法。

**结论：不符合“通用经验学习后，在陌生环境中自主探索、持续学习并执行多阶段目标”的预期。** 以前的有限仿真成功仍然成立，但不能用它认定 Minecraft 原型完成。当前实际表现是能够自主选择动作、记录部分经历，却没有形成可用于游戏目标的预测。

## 实际做了什么

使用 [Mojang 官方版本清单](https://piston-meta.mojang.com/v1/packages/a15eac24543d2a5e70f3ee28f033463adc1637e6/1.21.4.json)中的服务端，SHA-1 为 `4707d00eb834b446575d89a61a11b5d548d8c001`；使用官方分发的 Java 21.0.7。服务端监听本机回环地址，原版游戏机制负责动作结果。

A、B、C 是三个静态 Minecraft 房间。B、C 改变坐标、材质及物件位置；它们是最基本的场景迁移测试，不是开放世界生存测试。环境包含移动空间、音符方块、拉杆和活板门。场景构造与重置命令只存在于评估端，动作窗口内没有外部控制或结果回调。

Agent 只收到公开观测和现有身体动作。训练没有目标、子目标、解法或动作顺序。A 中自主执行 128 次动作；随后携带同一记忆进入 B，再自主执行 64 次。目标测试包括选择物品栏、转头、移动、组合条件、音符状态到达 `3`。目标使用结构化公开谓词，不代表自然语言理解。

## 观测结果

| 检查 | 真实结果 | 含义 |

| A 自主经验获取 | 128 次动作，71 次写入学习，57 次跳过 | 44.5% 的经历因前后感知通道不同而被拒收 |
| B 继续经验获取 | 64 次动作，38 次写入，26 次跳过 | 同一记忆累计 109 次更新，更新前整状态预测正确数仍为 0 |
| A 学习后，冻结规划 | 0/5 目标完成 | 在原环境中也尚未获得这些能力 |
| B 学习前，零样本迁移 | 0/5 | 无规划动作 |
| B 继续学习后，冻结规划 | 0/5 | 权重更新没有转化为可执行能力 |
| 返回 A 复测 | 0/5 | 不能据此声称遗忘，因为先前没有获得能力 |
| 全新 C 环境 | 0/5 | 无规划动作 |
| B 允许探索及即时学习 | 1/5 达成，77 次动作中规划动作 0 次 | 一次移动目标在探索中达成，不计为规划成功 |

主比较共 25 次目标检查，规划成功为 0。A/B 学习前后的检查对应不同记忆阶段；它们来自一个学习种子和一条 A→B 历程，不是 25 个独立环境样本。最终修复连接后的完整运行还完成了 25 次冻结复测，全部返回未知，全部保持记忆哈希不变；其中 A/B 有重复检查，不作为额外独立样本。

两阶段自主学习使用了移动、转头、跳跃、观察、等待、选择物品栏及一次破坏动作，**没有获得有效交互动作经历**。因此不能把这份经验称为充分的 Minecraft 常识。各已训练动作只有 1–7 次 A 阶段经历，亦未达到模型至少 16 次的执行门槛。更关键的结构性阻塞发生在该门槛之前，见下文。

287 个保留的真实事件窗口通过了事件完整性校验：269 个自主学习/目标探索窗口，18 个独立身体校准窗口。原始观测、动作回执、服务端日志、场景命令、世界存档和记忆快照均保留。

## 从第一性原理看，哪里错了

1. **把不断变化的视野当作固定输入面板。** A 学习后，模型累计了 651 个通道，而实际单帧只有 26–235 个。128 个训练起点没有一个覆盖累计通道集合，最少仍缺少 416 个。`predict()` 要求所有累计通道同时存在，因此连已经历过的场景也无法进入预测。继续在 B 学习后，通道增加到 1,171 个。增加训练次数不能取消这个检查。
2. **把对象坐标 ID 和连续数值当作独立词汇。** 世界中的位置变化会产生新的对象键和新的类别，不能共享已有经验。当前模型没有位置迁移或连续量外推的机制。
3. **要求预测整个可见场景，才允许完成局部目标。** 切换物品栏这样一个局部目标也会被无关方块的缺失阻塞。不能用“把未预测的字段原样复制到未来”修补，否则会制造未经验证的保持假设。
4. **探索选择不保证获得有用的交互经验。** 新奇度和全状态预测误差没有带来可靠的互动覆盖。现有记录能证明动作由 Agent 自主选择，不能证明它设计了有效的信息获取实验。
5. **存储规模与有效能力严重不相称。** A 阶段快照 JSON 已达 204,645,624 字节，却没有一个可执行预测；后续过程 RSS 曾约 3.7 GB。用稠密矩阵连接所有累计类别的代价增长过快，不值得围绕这个不适合场景迁移的表示继续做性能补丁。

这些结论来自代码条件和实测记录，不是对人类认知或物理介质学习一般可行性的否定。

## 已执行的修复及复测

- 修正了音符目标的数据类型：Minecraft 返回字符串 `"0"`、`"1"`，目标使用 `"3"`。初轮数值目标的结果不计入能力结论。
- 删除冻结测试中多余的模型复制，改为共享冻结记忆并核对前后哈希；压缩改为异步。仅在大操作之间让出执行时间的方案仍出现断线，该失败记录保留。
- 将现有 Minecraft 身体连接移入独立线程，保持观测与网络心跳独立于学习和快照计算。默认启动程序也使用同一连接方式。没有增加控制策略、效应规则或目标脚本。
- 原身体的公开动作目录提取为同一个静态函数，线程两侧复用，避免复制两份动作定义。
- 连接修复通过故意阻塞主线程 **35 秒**的实测：观测序号从 **3 到 703**，连接保持正常，之后仍能执行身体交互。最终完整冻结评估没有再发生连接超时。
- 独立身体校准在 A/B/C 均实际观察到 **0→1→2→3**，每个终态再经过五次观测确认。第一次校准首击未产生状态变化；增加初始化稳定等待并使用独立连接后复测通过，尚未单独隔离首击问题的全部原因。校准中的固定动作只验证身体和场景可达性，**不进入学习记忆、不计为 Agent 成功**。
- 新核心 13 项回归测试通过。历史完整测试组及旧晶格能力门未被改名或宣称通过。

连接问题得到修复，**学习与迁移缺陷尚未修复**。不应将“程序能稳定跑完失败测试”称为最终目标完成。

## 下一次应改什么

优先删除全局固定感知布局和绝对对象 ID 词汇表这一表示假设。下一版本需要能共享对象之间的经验、处理对象进入/离开视野，并表示连续量；缺测应保留为未知。随后把预测支持度落实到实际被预测的局部量及其条件，保留真实结果复核，不能通过降低置信门槛或复制未预测状态来获得表面成功。

在上述表示能通过不同位置、不同可见对象集合的单步迁移之前，不再增加规划层级、调大搜索深度或训练轮数。再检验探索是否增加可用交互覆盖，最后才检验多阶段组合与能力保留。新增效应必须从真实经历学习，不能内置“按音符方块”“先拉杆再开门”等规则。

这是一份尚待实施的核心重构计划。本轮没有把它写成已经修复或已经取得跨环境成功。

## 复现与 GitHub 状态

```sh
npm run test:experience
npm run minecraft:experience:live -- \
  --java /absolute/path/java21/bin/java \
  --server /absolute/path/server-1.21.4.jar \
  --output /absolute/path/new-run --training 128 --adaptation 64 --seed 41
```

输出目录必须不存在。能力条件不成立时退出码为 1；`status: completed` 只表示实验完整结束。已保存的记忆可通过 `--restore MEMORY.json.gz --frozen-only` 复测。运行大快照时可显式配置 Node 内存；最终冻结运行使用了 `--max-old-space-size=8192`。使用 `--calibrate-only --io-stall-ms 35000` 复现连接压力及独立身体校准。

详细计数见 [机器可读结果](minecraft-experience-results-2026-09-10.json)。重构和新增评估代码已在本地准备好，但 **GitHub 尚未同步**：普通 Git 推送没有登录凭据；已连接 GitHub 集成在创建文件树时返回 `403 Resource not accessible by integration`。用户已明确允许同步，阻塞来自连接权限，而非缺少用户提交授权。当前远端核对基线仍为 `7fe4157`。
