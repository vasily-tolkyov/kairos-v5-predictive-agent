# Kairos V5 架构说明

Kairos V5是一个研究性质的具身预测智能体原型。它把系统分成五个边界清楚的部分。

## 1. 感知与身体

Mineflayer连接独立的Minecraft本地世界。感知层只提供机器人真实可见、可听和可测的公开信息。身体层执行观察、转向、移动、跳跃、快捷栏、交互、攻击、破坏和放置等基础动作。未执行的指令、模型想象和工具异常不能成为经验。

## 2. 事件表达

R1不是Minecraft世界坐标的缩放。一个事件被表达为：主体、公开属性、相对变化、状态转移和事件内部进程。原地跳跃、按钮状态变化或执行后没有效果，都可以形成非伪造的事件；不同主体的变化保持分开。

## 3. 预测核心

- R1保存具体事件经验。
- R2保存事件路径类别。
- R2A保存经验适用条件，R3只在查询时形成瞬时调制。
- 三个介质拥有各自独立的三维坐标。
- 锚点由重复真实沉积自然形成，不能由训练接口直接创建语义对象。
- 预测副本只读，不把想象或分析结果写回经验。
- `recall`返回历史上发生过的事情；`predict`必须来自当前条件下的物理随机推演，二者不能混用。

## 4. 分析核心与工作区

当前版本通过Pi连接分析模型。模型只能使用七个受限工具读取观察、查询经验和预测、执行身体动作、维护意图、读取当前目标材料并报告结束。事实证据与模型笔记分开保存；框架不自动生成子目标或写死绕路、跳跃规则。

这部分当前仍使用LLM，且模型资格与完整实机闭环没有通过。未来可研究非语言分析核心：在临时工作区中保存目标、组合经验、调用预测试走候选方案，再依据真实结果学习何时回忆、推演、探索或行动。

## 5. 注意力与薄运行层

注意力关注动作目标、当前焦点和异常变化。有有效预测时比较预期和现实；没有预测支持时只能标记未知变化。注意力可以中断尚未执行的动作，但不替分析核心选择方案。运行层负责时钟、消息传递、计算Worker和经验保存，不承担隐藏规划。

## 冷启动

V5从空经验开始。前128条完整真实事件只用于一次性拟合并冻结唯一事件地图，随后按原体验时间沉积。达到这一门槛前，物理预测不可用是正常状态。当前成功持久化到64条，因而不能把工程接口运行正常等同为预测核心已经成熟。
